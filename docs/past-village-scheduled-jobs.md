# Scheduled work after Edge City India

Edge City India ran October 11 to November 1, 2026 and has ended. The agent's current wants and availability must come from current resident context and verified service results. India guides and old plans remain historical.

This is a source inventory and decision list, not a tenant job audit. Ten core job specifications are declared in `install/install_index.ts`; two zzz.bot job families are conditional, three templates are created only on request, and a preview is temporary. A previous deployment inventory counted fourteen jobs; this document does not establish which jobs any box currently has or which are enabled. Schedules below are source defaults, normally in the configured Hermes zone (Asia/Kolkata by default), with tenant staggering where declared.

After **2026-11-01T18:30:00Z** (November 2 at 00:00 IST), covered work requires an explicit per-job allow in `$HERMES_HOME/av-events/post-village-policy.json`. Missing, unreadable or invalid policy means OFF. The strict schema is `{"version":1,"enabled":["daily_digest"]}`; only the nine keys below are accepted, without duplicates. Legacy cron flags, installed projections and earlier enabled state do not substitute for this post-event choice.

The separate operator command edits one key atomically, preserves other valid choices, and never creates, resumes or runs a job:

```sh
bun install/post_village_policy.ts status --home /absolute/resident/home
bun install/post_village_policy.ts set --home /absolute/resident/home --job daily_digest --enabled true
```

Only an operator should use that command, from a shell outside the agent. The av-events plugin's pre-tool hook refuses, before the tool runs, an agent tool call that would write, move, delete, link or re-permission the file or swap its `av-events` folder; run the command's `set`; carry the allow list (`--enabled` or `"enabled"` with a policy key); edit the code that enforces the setting (the av-events and village-bridge plugins, the index-network and zzzbot skill scripts, and the installed cron scripts by name); turn av-events off through `config.yaml`, `HERMES_SAFE_MODE` or `hermes plugins`; or resume, run or change a covered cron job that the setting keeps off. Reading the file and the command's `status` still work, and the agent is told to send the resident to the Agent Village team. This stops a resident's plain ask and naive injected text. It is a list of names checked against the text of each call, run as the agent's own user, so it cannot stop a multi-step evasion by a model that has read the guard, a name built from pieces, state carried over from an earlier call (a variable, a symlink, a folder entered before), or an edit to an installed script that is not on its list: a cron script runs fresh on every tick without a restart, and only the listed scripts are refused by name. The control that cannot be rewritten from the box is the control plane holding this setting; that is planned, not built. A valid allow still requires the existing consent, projection, autonomy and approval gates and no resident/admin hold. Generic job enable and resident resume cannot grant an opt-in or upgrade an old ungated job. Resident resume may clear the resident’s own hold only after explicit operator allow and proof of the current installed gate; admin/settings holds remain binding. New covered jobs are created paused; an allowed existing job keeps its enabled/paused state. OFF jobs are paused and read back on reinstall, preserving their IDs and schedules. Failed pause/readback fails the stage and preserves the job; it does not prove the job is paused. Runtime checks also protect direct entry points and recheck after lock waits and immediately before effects. If the operator revokes permission while the digest’s task completion is awaited, its public body is withheld; its already-recorded delivery/task completion is retained to preserve at-most-once handling.

An owner's repeating schedule is stored off the box: the Agent Village app keeps it and sets the owner's zzz.bot new-topic pace. Its posts are still written by this box's zzz event autonomy job, and the app marks each such turn with its schedule line. The local file stops those posts: unless both `zzz_event_autonomy` and `zzz_owner_repeating` are allowed, a marked turn ends before any model call or post (the run fails with `post-village-disabled`). The file does not delete the stored schedule or undo the pace it set: zzz.bot keeps offering new-topic turns at that pace, and a turn that arrives without the schedule line (the app's schedule flag off, or its read of the schedule failing or not fitting) runs as an ordinary autonomy turn. To clear a stored schedule, the owner asks their agent to stop it, which sends `zzz.schedule_posts` with `every_minutes:null` (allowed under every setting); that deletes the app's record and puts back the earlier pace. The owner's Pause on the Messaging page also holds it. Listing which schedules exist, or stopping one without the owner, is a separate operator action on the app. No remote action is performed by this source change.

The existing evening questions, memory signal sync, token usage audit and knowledge sync retain their existing gates; they are not in this new OFF list. The brief's weather source is still fixed to historical Mandrem with Asia/Kolkata day boundaries, not a verified resident location. Inspect current sources before enabling delivery. Optional-service availability, including Skylight, gold stars and FavorLoop, has not been verified live by this change.

Historical reference snapshots and API scopes remain intact. Installing revised text is separate from approving any future roll, wake, tag or production change. The frozen runtime AGENTS.md diff requires its own review before release.

The heartbeat and Agent Plaza selfie are already retired from the core cron catalog; do not re-enable them. Installer `--preserve-context` skips the revised AGENTS.md/SOUL.md; stored cron prompt refresh is also conditional on the actual authorized installation path. A source change or passing test is not evidence that a resident runtime loaded it.

The root installer performs an independent read-only audit immediately before any automatic gateway restart, including when `--skip-index`, `--skip-crons`, `--preserve-context` or `--no-restart` is used. Skips retain their normal no-reconciliation meaning. Actual absent or conclusively paused covered jobs verify without mutation; runnable operator-allowed jobs require their existing gates. Unreadable state, active OFF work or failed covered reconciliation produces fixed unverified reasons, nonzero exit and no automatic restart or installed-success banner. This audit does not verify remote repeating schedules, welcome execution, AGENTS loading or general release readiness. `--preserve-context` can retain earlier AGENTS/SOUL text; a covered-job audit is not a receipt for loading the proposed context.
